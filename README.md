# recipe-ui

A reusable [StencilJS](https://stenciljs.com/) web component library built for the **Recipe Finder & Meal Planner** app. The components are framework-agnostic custom elements and are consumed by the companion [`recipe-finder-app`](../recipe-finder-app) SvelteKit project as an npm dependency (not by importing from source).

## Components

| Component | Purpose | Props | Events | Slots |
|---|---|---|---|---|
| `rf-button` | Themed button | `variant`, `disabled`, `type` | — (native `click` bubbles) | default |
| `rf-chip` | Selectable filter chip | `label`, `selected` | `chipToggle` | — |
| `rf-rating` | Star rating display/input | `value`, `readonly` | `ratingChange` | — |
| `rf-search-bar` | Debounced search input | `placeholder`, `value`, `debounce` | `searchChange` | `actions` |
| `rf-modal` | Dialog/modal | `open`, `heading` | `modalClose` | default (body), `footer` |
| `rf-recipe-card` | Recipe card | `mealId`, `recipeTitle`, `image`, `category`, `area`, `isFavorite`, `isCustom` | `favoriteToggle`, `viewRecipe` | `footer` |
| `rf-day-slot` | Meal-planner day cell | `day`, `recipeTitle`, `recipeImage`, `empty` | `addMeal`, `removeMeal` | default (empty-state content) |

Every component's full prop/event/slot API is auto-documented in its own `readme.md` under `src/components/<name>/` (generated by Stencil's `docs-readme` output target on every build).

All components render in a shadow root but read a small set of shared CSS custom properties (`--rf-color-primary`, `--rf-radius-md`, `--rf-shadow-sm`, etc. — see `src/global/global.css`) so a consuming app can theme them by setting the same variables on `:root`.

## Setup

```bash
npm install
```

## Development

```bash
npm start
```

Starts Stencil's dev server with live reload against `src/index.html`, a hand-written preview page that exercises every component's props, events, and slots.

## Building

```bash
npm run build
```

Produces:
- `dist/` — the `dist` output target (used via `dist/loader` for framework consumption) and the `dist-custom-elements` bundle
- `loader/` — the small ESM/CJS loader that exposes `defineCustomElements()`
- Per-component `readme.md` API docs (via the `docs-readme` output target)

## Consuming this library during local development (no registry required)

The SvelteKit app is meant to depend on this library as an **installed npm package**, not via a source import. Until this package is published to the npm registry, that's done with a local tarball:

```bash
# In recipe-ui/
npm run build
npm pack
# → produces recipe-ui-1.0.0.tgz (or similar)
```

Then, in the `recipe-finder-app` project:

```bash
npm install ../recipe-ui/recipe-ui-1.0.0.tgz
```

This installs the package into `recipe-finder-app/node_modules` exactly like a registry install would (`package.json` gets a `"recipe-ui": "file:../recipe-ui/recipe-ui-1.0.0.tgz"` dependency). Whenever a component changes, re-run `npm run build && npm pack` here, then `npm install` again in the app (npm does not watch `file:` tarball dependencies for changes).

The `pack:local` npm script does the build + pack in one step:

```bash
npm run pack:local
```

## Publishing to npm

1. **Check the name is actually available.** `package.json` currently publishes as the unscoped `recipe-ui` — a short, generic name that is very likely already taken on the public registry. Check first:
   ```bash
   npm view recipe-ui
   ```
   If that resolves to someone else's package, either pick a different unscoped name or switch to a scope you own, e.g. `@your-npm-username/recipe-ui` (rename `"name"` in `package.json`, then add back `"publishConfig": { "access": "public" }`, which is required the first time you publish a scoped package — otherwise npm defaults scoped packages to private, which needs a paid plan). Update the dependency line in `recipe-finder-app/package.json` and the imports in `src/lib/stencilInit.ts` / `src/lib/stencil.d.ts` to match whatever name you land on.
2. **Log in:**
   ```bash
   npm login
   ```
3. **Build and publish:**
   ```bash
   npm run build
   npm publish
   ```
4. **Versioning.** This package follows [semver](https://semver.org/). Bump the version before each publish using npm's built-in tooling rather than hand-editing `package.json`:
   ```bash
   npm version patch   # bug fixes / internal tweaks
   npm version minor    # new component or new prop/event, backwards compatible
   npm version major    # breaking change to an existing component's API
   npm publish
   ```

### Switching the app to the published package

Once published, update the SvelteKit app's dependency to point at the registry instead of the local tarball:

```bash
# in recipe-finder-app/
npm uninstall recipe-ui
npm install recipe-ui@^1.0.0
```

**Published package:** _add the npm registry link here after publishing, e.g. `https://www.npmjs.com/package/recipe-ui`_
